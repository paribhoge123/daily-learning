# Day 059: Cross-Validation

## What I Learned

Today I learned about **Cross-Validation**, a technique used to evaluate Machine Learning models more reliably.

Instead of depending on a single train-validation split, Cross-Validation evaluates the model across multiple different splits of the training data.

---

## Why Do We Need Cross-Validation?

A simple train-test split can produce a performance estimate that depends heavily on how the data was divided.

For example:

```text
Dataset
   ↓
80% Training
20% Testing
```

If the test set happens to be unusually easy or difficult, the evaluation may not represent the model's actual performance very well.

Cross-Validation helps reduce this dependency on one particular split.

---

# K-Fold Cross-Validation

The most common approach is **K-Fold Cross-Validation**.

For example, with:

```text
K = 5
```

the dataset is divided into five folds.

The model is trained and validated five times.

```text
          Fold1 Fold2 Fold3 Fold4 Fold5

Round 1     V     T     T     T     T
Round 2     T     V     T     T     T
Round 3     T     T     V     T     T
Round 4     T     T     T     V     T
Round 5     T     T     T     T     V
```

Where:

```text
V = Validation
T = Training
```

Every sample gets used for validation once and for training multiple times.

---

## Calculating the CV Score

Suppose the validation scores are:

```text
Fold 1 → 91%
Fold 2 → 89%
Fold 3 → 93%
Fold 4 → 90%
Fold 5 → 92%
```

The mean score is:

```text
(91 + 89 + 93 + 90 + 92) / 5
= 91%
```

The average gives us an overall estimate of the model's validation performance.

We can also examine the variation between fold scores to understand model stability.

---

# Why Cross-Validation is Useful

Cross-Validation helps with:

* More reliable performance estimation
* Comparing different models
* Hyperparameter tuning
* Detecting performance instability
* Reducing dependence on a single validation split

---

# Cross-Validation for Hyperparameter Tuning

Suppose we want to tune a Random Forest.

Possible hyperparameters include:

```text
n_estimators
max_depth
min_samples_split
```

We can evaluate different combinations using Cross-Validation.

```text
Hyperparameters
       ↓
Cross-Validation
       ↓
CV Score
       ↓
Compare Configurations
       ↓
Best Configuration
```

This helps us select hyperparameters using multiple validation splits rather than one.

---

# Train, Validation and Test Sets

A common workflow is:

```text
Dataset
   ↓
Train + Test Split
   ↓
Training Data
   ↓
Cross-Validation
```

The test set remains untouched.

For example:

```text
1000 Samples
     ↓
800 Training
200 Test
```

The 800 training samples can be evaluated using 5-fold cross-validation.

After selecting the final model:

```text
Final Model
     ↓
200 Unseen Test Samples
     ↓
Final Evaluation
```

---

# Why Should We Protect the Test Set?

If we repeatedly evaluate models on the test set:

```text
Train
 ↓
Test
 ↓
Change Model
 ↓
Test Again
 ↓
Change Model
 ↓
Test Again
```

we can gradually start optimizing our decisions based on the test data.

Then it is no longer a truly unseen evaluation set.

Therefore:

> The test set should ideally be used only for final evaluation.

---

# Choosing K

Common choices include:

```text
K = 5
K = 10
```

### 5-Fold

Usually a good practical choice.

### 10-Fold

Provides more validation rounds but requires more computation.

There is no universally best value of K.

---

# Stratified K-Fold

For classification problems, we often use **Stratified K-Fold**.

Suppose:

```text
90% → Class 0
10% → Class 1
```

Stratified K-Fold attempts to preserve approximately the same class distribution in each fold.

Example:

```text
Entire Dataset
90% Class 0
10% Class 1

       ↓

Fold 1 → ~90/10
Fold 2 → ~90/10
Fold 3 → ~90/10
...
```

This is particularly useful when classes are imbalanced.

---

# Time Series Cross-Validation

Standard K-Fold is often inappropriate for time-series data because it can mix future and past observations.

For example:

```text
Train → January
Validate → February

Train → January + February
Validate → March

Train → January + February + March
Validate → April
```

This respects chronological order.

---

# Data Leakage During Cross-Validation

Preprocessing must be performed correctly inside each fold.

Incorrect:

```text
Entire Dataset
      ↓
Standardization
      ↓
Cross-Validation
```

Correct:

```text
Training Fold
      ↓
Fit Scaler
      ↓
Transform Training Fold
      ↓
Transform Validation Fold
      ↓
Train Model
      ↓
Evaluate
```

Machine Learning pipelines can help automate this process correctly.

---

# Train-Test Split vs Cross-Validation

| Train-Test Split          | Cross-Validation                      |
| ------------------------- | ------------------------------------- |
| Usually one split         | Multiple splits                       |
| Faster                    | More computationally expensive        |
| Simple                    | More robust evaluation                |
| Depends on one split      | Less dependent on one split           |
| Useful for large datasets | Useful for model selection and tuning |

---

# Important Insight

Cross-Validation does not directly improve the model.

Instead, it helps us make better decisions about:

* Which model to use
* Which hyperparameters to choose
* How stable the model is
* How well the model is likely to generalize

The final model should still be evaluated on an untouched test set.

---

# Overall ML Workflow

```text
Raw Data
   ↓
Train/Test Split
   ↓
Cross-Validation
   ↓
Preprocessing
   ↓
Feature Engineering
   ↓
Feature Selection
   ↓
Model Training
   ↓
Hyperparameter Tuning
   ↓
Final Model
   ↓
Unseen Test Data
   ↓
Final Evaluation
```

---

# Key Takeaways

* Cross-Validation evaluates a model across multiple train-validation splits.
* K-Fold is one of the most common approaches.
* 5-Fold and 10-Fold are common choices.
* Stratified K-Fold is useful for classification.
* Time-aware validation is important for time-series data.
* Cross-Validation is useful for model selection and hyperparameter tuning.
* The test set should remain untouched until final evaluation.
* Preprocessing must be performed without leaking information between folds.
* Cross-Validation improves the reliability of model evaluation, not the model itself.
