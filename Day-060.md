# Day 060 — Hyperparameter Tuning: Grid Search & Random Search

## 📌 Overview

Hyperparameter tuning is the process of finding the best hyperparameter values for a machine learning model.

Hyperparameters are settings that are chosen before the model is trained.

Examples:

* `max_depth` in Decision Trees
* `n_estimators` in Random Forest
* `n_neighbors` in KNN
* `learning_rate` in Gradient Boosting

The goal of hyperparameter tuning is to find a configuration that gives good performance on unseen data.

---

## 1. Parameters vs Hyperparameters

### Parameters

Parameters are learned automatically from training data.

Example:

* Neural network weights
* Linear regression coefficients

### Hyperparameters

Hyperparameters are selected before training.

Example:

```text
Random Forest:
n_estimators = 100
max_depth = 10
```

| Parameters              | Hyperparameters        |
| ----------------------- | ---------------------- |
| Learned during training | Set before training    |
| Learned from data       | Chosen by us           |
| Example: weights        | Example: learning rate |

---

## 2. Why Hyperparameter Tuning?

Different hyperparameter values can produce very different results.

For example:

```text
max_depth = 3   → 88% accuracy
max_depth = 5   → 91% accuracy
max_depth = 10  → 94% accuracy
max_depth = 20  → 92% accuracy
```

The goal is to find the configuration that performs best according to the chosen evaluation metric.

---

# 3. Grid Search

Grid Search evaluates every combination of hyperparameters from a predefined search space.

For example:

```python
max_depth = [3, 5, 7]
n_estimators = [50, 100]
```

Grid Search evaluates:

```text
(3, 50)
(3, 100)
(5, 50)
(5, 100)
(7, 50)
(7, 100)
```

Total combinations:

```text
3 × 2 = 6
```

---

## 4. GridSearchCV

Scikit-learn provides `GridSearchCV` for combining Grid Search with Cross-Validation.

```python
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import GridSearchCV

model = RandomForestClassifier(random_state=42)

param_grid = {
    "n_estimators": [50, 100, 200],
    "max_depth": [5, 10, 15]
}

grid_search = GridSearchCV(
    model,
    param_grid,
    cv=5,
    scoring="accuracy"
)

grid_search.fit(X_train, y_train)

print(grid_search.best_params_)
print(grid_search.best_score_)
```

`cv=5` means that 5-fold Cross-Validation is used to evaluate each hyperparameter combination.

---

# 5. Random Search

Random Search does not evaluate every possible combination.

Instead, it randomly samples combinations from the specified search space.

This can be much faster when the search space is large.

---

## 6. RandomizedSearchCV

```python
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import RandomizedSearchCV

model = RandomForestClassifier(random_state=42)

param_distributions = {
    "n_estimators": [50, 100, 200, 300],
    "max_depth": [5, 10, 15, 20],
    "min_samples_split": [2, 5, 10]
}

random_search = RandomizedSearchCV(
    model,
    param_distributions=param_distributions,
    n_iter=10,
    cv=5,
    scoring="accuracy",
    random_state=42
)

random_search.fit(X_train, y_train)

print(random_search.best_params_)
print(random_search.best_score_)
```

Here:

```python
n_iter=10
```

means that 10 randomly selected hyperparameter combinations are evaluated.

---

# 7. Grid Search vs Random Search

| Feature            | Grid Search             | Random Search             |
| ------------------ | ----------------------- | ------------------------- |
| Approach           | Tests every combination | Tests random combinations |
| Speed              | Usually slower          | Usually faster            |
| Computational cost | Higher                  | Lower                     |
| Exhaustive         | Yes                     | No                        |
| Best for           | Small search spaces     | Large search spaces       |

### Simple rule

```text
Small search space → Grid Search

Large search space → Random Search
```

---

# 8. Hyperparameter Tuning + Cross-Validation

Hyperparameter tuning becomes more reliable when combined with Cross-Validation.

For example:

```text
Hyperparameter Combination A

Fold 1 → 91%
Fold 2 → 94%
Fold 3 → 92%
Fold 4 → 93%
Fold 5 → 95%

Mean CV Score → 93%
```

The same process is performed for other combinations.

The combination with the best CV score can then be selected.

---

# 9. Complete Workflow

```text
Raw Data
   ↓
Train/Test Split
   ↓
Preprocessing
   ↓
Choose Model
   ↓
Define Hyperparameter Search Space
   ↓
Grid Search / Random Search
   ↓
Cross-Validation
   ↓
Select Best Hyperparameters
   ↓
Train Best Model
   ↓
Evaluate on Test Set
```

---

# 10. Why Keep the Test Set Separate?

The test set should not be repeatedly used during hyperparameter tuning.

If we repeatedly optimize against the test set, the model-selection process can indirectly overfit to it.

Instead:

```text
Training Data
     ↓
Cross-Validation
     ↓
Hyperparameter Tuning
     ↓
Best Model
     ↓
Final Test Evaluation
```

The test set should ideally be used only for the final unbiased evaluation.

---

# 11. Feature Engineering vs Hyperparameter Tuning

These concepts are different.

### Feature Engineering

Changes or creates input features.

Example:

```text
Date
 ↓
Day + Month + Year
```

### Hyperparameter Tuning

Changes model configuration.

Example:

```text
Decision Tree

max_depth = 5
max_depth = 10
max_depth = 15
```

Therefore:

```text
Feature Engineering
→ Improve the representation of the data

Hyperparameter Tuning
→ Find better model settings
```

---

# 12. Choosing the Right Metric

The best hyperparameters depend on the evaluation metric.

Possible metrics include:

* Accuracy
* Precision
* Recall
* F1-score
* ROC-AUC
* Mean Squared Error
* Mean Absolute Error

For imbalanced classification problems, accuracy alone may not be a suitable metric.

---

# 🧠 Key Takeaways

1. Hyperparameters are settings chosen before training.
2. Hyperparameter tuning searches for good model configurations.
3. Grid Search tests every specified combination.
4. Random Search tests randomly selected combinations.
5. Cross-Validation can be used to evaluate each configuration.
6. Grid Search is useful for smaller search spaces.
7. Random Search is useful for larger search spaces.
8. The test set should remain separate until final evaluation.
9. Hyperparameter tuning and feature engineering solve different problems.
10. The evaluation metric should match the actual ML problem.
